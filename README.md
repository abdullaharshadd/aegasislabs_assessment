## Migration Notes

The following summarises what changed when moving from the Python/Django codebase to Go standard library:

### Framework

| Before (Django) | After (Go) |
|---|---|
| Django URL routing (`urls.py`) | `net/http` `ServeMux` route registration in `main.go` |
| Django views (`views.py`) | Go handler functions (`func(w http.ResponseWriter, r *http.Request)`) |
| Django settings (`settings.py`) | Environment variables loaded at startup |
| Django ORM / models | **Not migrated** — see Known Limitations |
| `manage.py runserver` | `go run ./...` |

### OpenAI Client

The original `client.py` used the deprecated `openai` Python SDK calling `openai.Completion.create` with `engine='text-davinci-002'`. The migrated Go client requires manual rewriting to use a supported endpoint and model. See [Known Limitations](#known-limitations).

### In-Memory State

The original Django application maintained a global in-memory `prompts` list inside `ChatGPTBotAPI`. This pattern was carried into the Go migration but is **not safe** for multi-worker or multi-instance deployments and is **not persistent** across restarts.

## Known Limitations

The following components could **not** be automatically migrated and contain broken or placeholder implementations:

### 1. `main.py` — Deprecated OpenAI Completions endpoint

| | |
|---|---|
| **Component** | `openai.Completion.create` with `engine='text-davinci-002'` |
| **Reason** | Uses the deprecated Completions endpoint and a retired model (`text-davinci-002`) that is no longer available in the current OpenAI API. |
| **Impact** | All API calls to OpenAI will fail at runtime. |
| **Fix** | Rewrite the OpenAI call in `client.go` to use the Chat Completions endpoint with a supported model: |

```go
// Example using the official Go OpenAI SDK (github.com/sashabaranov/go-openai)
resp, err := client.CreateChatCompletion(
    context.Background(),
    openai.ChatCompletionRequest{
        Model: openai.GPT4oMini, // or openai.GPT3Dot5Turbo
        Messages: []openai.ChatCompletionMessage{
            {Role: openai.ChatMessageRoleUser, Content: userPrompt},
        },
    },
)
```

---

### 2. `main.py` — In-memory `prompts` list (ChatGPTBotAPI)

| | |
|---|---|
| **Component** | `ChatGPTBotAPI` global in-memory prompts list |
| **Reason** | Global in-memory state is not safe for stateless/multi-worker deployments and is lost on every restart. Automatic migration would preserve broken semantics. |
| **Impact** | Conversation history is not persisted. Multiple concurrent workers or server restarts will lose all prompt history. |
| **Fix** | Replace with a persistent store. Options: |

- **Database:** Add a `prompts` table (e.g., via `database/sql` with PostgreSQL or SQLite) and insert each prompt/response pair.
- **Cache:** Use Redis with a session key to store per-user conversation history.
- **Simplest path:** For a stateless single-turn API, remove the history list entirely and send only the current user message.
